# 카카오 대중교통 API 호출 검증

## 1. 검증 목적

지금 나가 서비스에서 대중교통 경로 조회 기능을 구현하기 위해 카카오맵 대중교통 API의 호출 가능 여부와 응답 구조를 검증한다.

## 2. API 기본 정보

| 항목 | 내용 |
|---|---|
| API | 카카오맵 대중교통 경로 조회 |
| HTTP Method | GET |
| Endpoint | `https://dapi.kakao.com/v2/routing/publictraffic` |
| 인증 방식 | REST API 키 (`Authorization: KakaoAK {REST_API_KEY}`) |
| 요청 파라미터 | 출발지 경도·위도, 도착지 경도·위도 |
| 응답 형식 | JSON |

### 요청 파라미터

| 파라미터 | 설명 |
|---|---|
| `start_x` | 출발지 경도 |
| `start_y` | 출발지 위도 |
| `end_x` | 도착지 경도 |
| `end_y` | 도착지 위도 |

## 3. API 호출 검증 결과

기존 지금 나가 카카오 앱의 REST API 키를 사용하여 PowerShell에서 직접 API를 호출했다.

- API 요청 및 인증 성공
- 응답 상태 `OK` 확인
- 총 15개의 대중교통 경로 반환
- 버스 9개, 지하철 2개, 버스·지하철 혼합 4개 경로 확인

### 응답 구조

```text
response
├── status
├── properties
│   ├── total
│   ├── bus
│   ├── subway
│   ├── busAndSubway
│   └── landingURL
└── routes[]
    ├── properties
    │   ├── type
    │   ├── totalDistance
    │   ├── totalTime
    │   ├── transfers
    │   └── fare
    │       ├── min
    │       └── max
    └── steps[]
        ├── properties
        └── path
            └── points
```

## 4. 경로별 요약 정보

첫 번째 버스 경로에서 다음 데이터를 확인했다.

| 필드 | 확인된 값 | 단위 |
|---|---|---|
| `type` | BUS | - |
| `totalDistance` | 6328 | m |
| `totalTime` | 1582 | 초 |
| `transfers` | 1 | 회 |
| `fare.min` | 1550 | 원 |
| `fare.max` | 1650 | 원 |

이를 통해 총 이동거리, 예상 소요시간, 환승 횟수, 예상 요금을 조회할 수 있음을 확인했다.

## 5. 이동 구간별 정보

경로의 `steps` 배열에서 이동수단별 상세 정보를 확인했다.

확인된 이동수단 유형은 다음과 같다.

- `BUS`: 버스 이동 구간
- `SUBWAY`: 지하철 이동 구간
- `WALKING`: 도보 이동 구간

### 구간별 응답 정보

`steps[].properties`에서 다음 정보를 확인했다.

- `type`: 이동수단 유형
- `distance`: 구간 이동거리
- `time`: 구간 소요시간
- `guidance`: 이동 안내 문구
- `stops`: 정류장 또는 역 정보
- `vehicles`: 이용 가능한 노선 정보 (버스 구간에서 확인)

`steps[].path.points`에서는 지도에 경로를 표시하기 위한 좌표 배열을 확인했다.

### 도보 구간 검증

| 항목 | 확인된 값 |
|---|---|
| 이동수단 | WALKING |
| 이동거리 | 271m |
| 예상 소요시간 | 334초 |
| 경로 좌표 | 9개 |

도보 구간의 거리, 소요시간, 경로 좌표가 반환되는 것을 확인했다.

따라서 이번에 검증한 대중교통 경로 조회에서는 도보 구간을 위해 별도의 도보 길찾기 API를 호출할 필요가 없다.

## 6. 카카오맵 무료 쿼터

카카오 디벨로퍼스에서 지금 나가 앱의 카카오맵 사용 설정을 확인했다.

- 카카오맵 사용 상태: ON
- 카카오맵 무료 쿼터 적용 앱 표시 확인
- 대시보드에서 일간 무료 쿼터 제공 안내 확인

대중교통 경로 조회의 무료 호출 한도는 일 1,000건으로 안내되어 있다.

실제 호출량과 잔여 쿼터는 카카오 디벨로퍼스의 통계 메뉴에서 별도로 확인해야 한다.

## 7. 백엔드 연동 시 고려사항

### API 키 관리

- 기존 카카오 앱의 REST API 키를 재사용한다.
- API 키는 환경변수로 관리하고 Git에 커밋하지 않는다.
- 카카오 로그인 및 장소 검색 기능에 영향을 주지 않도록 기존 설정을 확인한다.

### 응답 데이터 처리

- 외부 API 응답 DTO와 서비스 응답 DTO를 분리한다.
- 거리와 시간의 단위를 명확하게 관리한다.
- 경로가 없는 경우와 API 오류를 구분하여 처리한다.
- 한글 안내 문구의 UTF-8 인코딩을 확인한다.

### API 호출량 관리

- 동일한 출발지·도착지 경로에 대한 반복 호출을 줄인다.
- Redis 캐싱 도입을 검토한다.
- 호출 한도 초과 및 외부 API 장애에 대한 예외 처리를 구현한다.

## 8. 최종 결론

카카오 대중교통 API 호출 검증 결과, 지금 나가 서비스에서 필요한 주요 대중교통 경로 데이터를 조회할 수 있음을 확인했다.

- 대중교통 경로 목록 조회 가능
- 버스·지하철·도보 구간 구분 가능
- 예상 소요시간·거리·환승 횟수·요금 조회 가능
- 구간별 경로 좌표 조회 가능
- 현재 카카오 앱에 무료 쿼터 적용 확인

따라서 카카오 대중교통 API를 기반으로 백엔드 경로 조회 기능을 구현한다.

단, 실제 서비스 연동 시 오류 응답, 호출 한도, 다양한 출발지·도착지 조합에 대한 추가 테스트가 필요하다.
